🎯 Introducción y Visión

Objetivo Principal

Crear un ecommerce profesional, escalable y fácil de administrar que permita a Flor vender productos personalizados sin depender de terceros.

Filosofía del Proyecto

✓ Simplicidad

Simplicidad antes que complejidad técnica

✓ Código Limpio

Código limpio > código "clever"

✓ Estabilidad

Estabilidad > features "cool"

✓ Admin Intuitivo

Sin conocimientos técnicos necesarios

✓ Control Total

100% control en manos de Puchia

✓ Mantenibilidad

Fácil de mantener y actualizar

Estimación de Tiempo

2-3 semanas para MVP (Producto Mínimo Viable)

Stack Tecnológico Sugerido

  • Frontend: React o Vue.js
  • Backend: Node.js + Express (o Python + FastAPI)
  • Base de datos: PostgreSQL
  • Hosting: Hostinger (Node.js)

🏗️ Arquitectura General del Sistema

El sistema consta de TRES aplicaciones web independientes pero conectadas:

1. TIENDA CLIENTE

Estado: 90% funcional
Función: Vitrina, carrito, checkout
URL: puchia.com.ar

2. PANEL ADMIN

Estado: 85% funcional
Función: Gestión productos/stock/órdenes
URL: /admin

3. BACKEND API

Estado: NO INICIADO - PRIORIDAD MÁXIMA
Función: Procesa datos, BD, lógica
URL: api.puchia.com.ar

4. BASE DE DATOS

Estado: NO INICIADO
Tipo: PostgreSQL
Función: Persistencia de datos

🗂️ Entidades Principales

PRODUCTO

  • ID, nombre, precio, descripción HTML
  • Múltiples categorías
  • Estado (habilitado/deshabilitado)
  • Media (imágenes, videos)
  • Stock Type: "simple" o "insumo"
  • Atributos: tamaño, color, etc.

INSUMO

  • ID, nombre, stock actual
  • Descripción opcional
  • Vinculado a múltiples productos
  • Mapeado por colores

ORDEN

  • ID único (ej: ORD-1715800000000)
  • Datos del cliente (nombre, email, DNI, teléfono)
  • Items ordenados con atributos
  • Total y estado
  • Notas personalizadas

Ejemplo Producto con Insumo

{ "id": 1, "nombre": "Vaso Personalizado", "precio": 1290, "stockType": "insumo", "insumoId": 2, // ← Vaso Plástico Rojo "atributos": { "tamaño": ["Chico", "Mediano", "Grande"], "color": [ {name: "Rojo", hex: "#FF0000"}, {name: "Azul", hex: "#0000FF"} ] }, "colorInsumoMap": { "Rojo": 1, // Vaso Plástico Rojo "Azul": 2 // Vaso Plástico Azul } }

🛡️ Seguridad, Performance, Escalabilidad

Seguridad

  • HTTPS obligatorio en producción
  • Validación de datos en BACKEND (nunca confiar en frontend)
  • SQL Injection: Usar ORM (Sequelize) o prepared statements
  • CSRF tokens en formularios
  • Rate limiting en API (evitar ataques DDoS)
  • Contraseñas hasheadas con bcrypt
  • JWT con expiración de tokens
  • CORS configurado correctamente
  • Variables de entorno (.env) para secretos

Performance

  • Lazy loading de imágenes/videos
  • Caché en cliente (HTTP cache headers)
  • Compresión Gzip en servidor
  • CDN para media (Cloudflare, AWS CloudFront)
  • Índices en BD en campos búsquedos frecuentemente
  • Paginación en grandes listas
  • Queries optimizadas (evitar N+1 queries)

Escalabilidad

  • Arquitectura modular (componentes React independientes)
  • API RESTful estándar
  • BD normalizada para evitar redundancia
  • Desacoplamiento frontend-backend
  • Versionamiento de API (/api/v1/)
