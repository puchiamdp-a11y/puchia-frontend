1️⃣ Aclaraciones Críticas Sobre Tecnología

Las tecnologías mencionadas en este documento son ÚNICAMENTE orientativas.

NO representan decisiones definitivas e inamovibles.

¿Qué puede cambiar?

  • Base de datos: SQLite → PostgreSQL o MongoDB si crece
  • Frontend: Vanilla JS → React/Vue si se complica
  • Backend: Express → Django/FastAPI si es mejor
  • Hosting: Hostinger → AWS/Google Cloud si requiere escala

Criterios para Cambios Técnicos

Se cambia tecnología si... Ejemplo
Mejora la simplicidad Un framework simplifica el código 50%
Mejora la estabilidad Una BD relacional garantiza integridad de datos
Mejora mantenimiento Framework con documentación oficial + comunidad
Mejora administración Panel admin visual en lugar de configs manual
Permite escalabilidad futura Arquitectura que aguante 10x de usuarios

Lo que NO cambió

  • ✅ Objetivo: ecommerce profesional y escalable
  • ✅ Filosofía: simplicidad + estabilidad
  • ✅ Identidad: colores, tipografía, estética Puchia
  • ✅ Facilidad de administración: Flor puede usarlo sin códigos

2️⃣ Aclaraciones Sobre Logo & Identidad Visual

La IA no interpreta correctamente el logo original de Puchia.

La descripción actual es únicamente orientativa y provisoria.

Qué NO hacer

  • ❌ NO asumir formas exactas del logo
  • ❌ NO asumir significados simbólicos "correctos"
  • ❌ NO rediseñar automáticamente el logo
  • ❌ NO generar versiones "creativas" sin aprobación manual

Qué SÍ hacer

  • ✅ Utilizar únicamente referencias visuales aprobadas manualmente
  • ✅ Considerar cualquier descripción textual como TEMPORAL
  • ✅ Ante duda sobre logo, preguntar antes de implementar
  • ✅ Usar emojis/placeholders para mockups hasta tener logo vectorizado

Cuándo se resuelve esto

Una vez disponibles:

  • Archivo vectorial del logo (.svg o .ai)
  • Guía de marca oficial de Puchia
  • Versiones en diferentes formatos (light/dark, en color/gris)
  • Reglas de espaciado y uso correcto

🔟 Plan de Deployment a Hostinger

Opción Elegida: Node.js Hosting

Por qué: Más fácil, automático, sin configuración avanzada

Pasos (Simplificados)

1. Registrarse en Hostinger

Crear cuenta y plan Node.js

2. Crear aplicación

Panel → Aplicaciones → Node.js → Nueva

3. Conectar repositorio

GitHub/GitLab con código del proyecto

4. Configurar variables

.env con ADMIN_PASSWORD, WHATSAPP_NUMBER

5. Deploy

Click botón → Hostinger despliega automáticamente

6. Obtener dominio provisorio

puchia123.hostinger.com (mientras tanto)

7. Testear desde otros dispositivos

Acceso desde celular, tablet, otra ciudad

8. Comprar dominio propio (opcional)

puchia.com.ar → Conectar cuando esté listo

Costo Aproximado

Concepto Costo
Hosting Hostinger (Node.js) ~$200-350 ARS/mes
Dominio (.com.ar) ~$500-800 ARS/año
TOTAL ANUAL ~$2.000-4.000 ARS
